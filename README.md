# WukongBenchAuto

Консольно-оконный инструмент на C# (.NET 8, Windows) для локального автоматизированного
запуска **Black Myth: Wukong Benchmark Tool** из Steam: два прохода бенчмарка
(CPU-тест и GPU-тест) с разными профилями настроек графики, автоматический сбор
результатов и формирование отчётов `report.json` и `report.html`.

Основной сценарий полностью автоматический: от запуска инструмента до получения
результатов обоих тестов, без ручных действий пользователя.

## Требования

- Windows 10/11 x64
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (для сборки)
- Установленный Steam и **Black Myth: Wukong Benchmark Tool** (AppID `3132990`)
- Запущенный Benchmark Tool хотя бы один раз вручную (чтобы создался
  `b1\Saved\Config\Windows\GameUserSettings.ini`)

## Сборка

```powershell
dotnet build --configuration Release
```

## Запуск

Одной командой (WinForms-окно с кнопкой запуска, логом и редактором профилей):

```powershell
dotnet run --configuration Release
```

Полностью автоматический прогон без окна (консольный режим):

```powershell
dotnet run --configuration Release -- --cli
```

Или собранным exe:

```powershell
.\bin\Release\net8.0-windows\WukongBenchAuto.exe          # окно
.\bin\Release\net8.0-windows\WukongBenchAuto.exe --cli    # консоль
```

Проверка автопоиска без запуска бенчмарка:

```powershell
.\bin\Release\net8.0-windows\WukongBenchAuto.exe --cli --check
```

Во время автоматизации меню (первые ~35 секунд после появления окна игры)
**не трогайте мышь и клавиатуру** — инструмент сам нажимает Space, выбирает
«Тест быстродействия» и подтверждает запуск.

## Способы указания пути к игре

Инструмент находит папку Benchmark Tool в следующем порядке:

1. **Аргумент командной строки** `--path "<папка>"` (или `-p`). Проверяется,
   что в папке есть `b1_benchmark.exe` и `b1\Binaries\Win64\b1-Win64-Shipping.exe`:

   ```powershell
   .\WukongBenchAuto.exe --cli --path "D:\SteamLibrary\steamapps\common\Black Myth Wukong Benchmark Tool"
   ```

2. **Конфиг** `config.json` рядом с exe — путь, сохранённый при прошлом запуске.
   Автоматически обновляется после успешного определения пути.

3. **Автопоиск через Steam**: ключ реестра
   `HKLM\SOFTWARE\WOW6432Node\Valve\Steam` / `HKCU\Software\Valve\Steam`,
   затем `libraryfolders.vdf` (все библиотеки Steam), перебор всех библиотек
   и поиск папки `Black Myth Wukong Benchmark Tool` в `steamapps\common`.

4. **Ручной ввод** в консоли — если автопоиск не удался, CLI-режим предложит
   ввести путь с проверкой наличия файлов бенчмарка; в WinForms-режиме — кнопка
   «Указать папку...». Введённый путь сохраняется в `config.json`.

## Структура отчёта

После прогона создаются два файла рядом с exe:

- **`report.json`** — машина-читаемый отчёт: системная информация, полные
  результаты обоих проходов (FPS avg/min/max/95, времена кадра CPU/GPU,
  видеопамять, счётчик кадров), фактически применённые настройки и средняя
  загрузка CPU/GPU за проход.
- **`report.html`** — самодостаточная страница без внешних зависимостей,
  адаптивная, с тёмной и светлой темами (по настройке системы). Блоки:
  «Система», «CPU-тест», «GPU-тест» (крупный avg FPS + метрики + определение
  ограничителя по временам кадра), «Настройки» (сравнение двух наборов
  в таблице).

Ключевой признак узкого места — сравнение среднего времени кадра:

- `CPUFrameTime > GPUFrameTime` → упор в **CPU**;
- иначе — упор в **GPU**.

## Как это работает

Всё нижеперечисленное установлено эмпирически на Benchmark Tool v1.0.3.14649.

1. **Запуск.** Через `steam.exe -applaunch 3132990`. Прямой запуск
   `b1_benchmark.exe` не используется (Steam должен инициализировать окружение).
   AppID находится в `appmanifest_3132990.acf` библиотеки Steam.

2. **Настройки.** Хранятся в
   `<папка игры>\b1\Saved\Config\Windows\GameUserSettings.ini`:
   пары `UISettingData=(("Ключ", "Значение"),...)` (качества, RTX, DLSS,
   генерация кадров, VSync) и секция `[ScalabilityGroups]` (`sg.*` —
   движковые уровни качества), плюс ключи разрешения и `FrameRateLimit`.
   Перед изменением делается резервная копия ini (в `%TEMP%\GameUserSettings.ini.bak`
   и в памяти процесса); после обоих проходов — включая падение или Ctrl+C —
   исходные настройки восстанавливаются.

3. **Автоматизация меню.** После появления окна `b1-Win64-Shipping` инструмент
   ждёт ~30 секунд (загрузка движка и шейдеров), затем через Win32 `SendInput`
   нажимает Space («нажмите любую клавишу»), кликает по кнопке
   «Тест быстродействия» и кнопке «Подтвердить». Координаты заданы в долях
   клиентской области окна и не зависят от разрешения. Во время кликов окно
   игры должно быть активно.

4. **Завершение теста.** Результат дописывается в JSON-файл
   `%TEMP%\b1\BenchMarkHistory\Tool\<unix-time>` (файл без расширения,
   имя — время начала теста). Инструмент следит за появлением нового файла
   в этой папке, дожидается завершения процесса игры и разбирает JSON.

5. **Формат результатов.** Агрегаты: `FPSAvg/FPSMin/FPSMax/FPS95`,
   `CPUAvg/GPUAvg`, `VideoMem`, плюс `Records[]` — по кадру:
   `FrameRate`, `CPUUsage`, `GPUUsage`, `CPUFrameTime`, `GPUFrameTime`,
   `VideoMemoryUsage`. Там же — системка (`CPUModel`, `GPUModel`,
   `GpuDriverVer`, `VideoMemSize`, `SysMem`, `SysVer`, `GameVer`) и
   применённые настройки. Результаты доступны только в этом JSON — UI Automation
   и OCR не требуются.

## Профили настроек и обоснование

Оба профиля: DX12, **VSync выключен**, **лимит FPS = 0** (без ограничений),
DLSS и генерация кадров выключены — чтобы результаты обоих проходов
сравнивались напрямую.

### CPU-тест (упор в процессор)

- Разрешение **1280×720**, масштаб рендера (`ImageQuality`/
  `sg.ResolutionQuality`) **25%** — минимальная нагрузка на GPU.
- Все качества графики на минимуме: тени, текстуры, материалы, растительность,
  эффекты, глобальное освещение, отражения, сглаживание, постобработка,
  дальность прорисовки — уровень 1. RTX выключен.
- При такой конфигурации видеокарта не является ограничителем: частота кадров
  определяется скоростью процессора (движок, логика сцены, подготовка кадров).

### GPU-тест (упор в видеокарту)

- **Нативное разрешение монитора** (определяется автоматически через WMI),
  масштаб рендера 100%.
- Все качества на максимуме (уровень 5), трассировка лучей включена
  (`Rtx=1`, `RtxLevel=3`, `sg.RayTracingQuality=3`).
- Апскейлинг (DLSS) и генерация кадров выключены — нагрузка на GPU не занижается.

### Подтверждение нагрузки

Во время каждого прохода сэмплируется загрузка CPU (Performance Counter
`Processor % Processor Time`) — средние значения попадают в отчёт
(`Load` в `report.json`), подтверждая, что тест действительно упёрся
в ожидаемый компонент.

### Редактор профилей (WinForms)

В окне программы — вкладки «CPU-профиль» и «GPU-профиль»: разрешение, масштаб
рендера, все качества сцен (1–5) и переключатели (RTX, DLSS, генерация кадров,
Motion Blur, VSync). Перед прогоном используются значения из полей, кнопка
«Сбросить профили к стандартным» возвращает заводские. DX12 и лимит FPS
зафиксированы (DX12=1, лимит=0), чтобы проходы оставались сравнимыми.
CLI-режим всегда использует стандартные профили.

## Известные ограничения

- Во время автоматизации меню окно игры должно быть **на переднем плане**;
  сворачивание окна или движение мыши в момент кликов собьёт сценарий.
- Окно игры не должно закрываться пользователем до конца прохода.
- Автопоиск Steam опирается на стандартные ключи реестра и `libraryfolders.vdf`;
  при нестандартной установке используйте `--path`.
- Работа проверена на Benchmark Tool v1.0.3.14649; на других версиях координаты
  меню и формат результатов могут измениться.
- Результаты чувствительны к фону: фоновые задачи (браузер, загрузки) искажают
  оба прохода.

## Структура проекта

```
Program.cs            — точка входа: WinForms-режим или CLI (--cli)
CliProgram.cs         — консольный автоматический прогон
MainForm.cs           — WinForms-оболочка (лог, кнопка запуска, выбор папки, редактор профилей)
ProfileEditorPanel.cs — панель-редактор одного профиля (разрешение, качества 1–5, переключатели)
Core/
  Config/             — конфиг (config.json) и поиск Steam/игры
  Settings/           — профили CPU/GPU и применение настроек к ini
  Launch/             — запуск через Steam и автоматизация меню
  Runner/             — оркестрация прохода: настройки → запуск → ожидание → парсинг
  Parsing/            — разбор JSON-результатов бенчмарка
  Hardware/           — монитор/ RAM/загрузка CPU (WMI, PerformanceCounter)
  Reporting/          — консольный вывод, report.json, report.html
tests/                — xUnit-тесты чистой логики (ini-профили, парсер, поиск, отчёт)
```
